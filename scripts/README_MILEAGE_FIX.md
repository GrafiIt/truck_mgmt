# 총주행거리(total_mileage) 관리 시스템 문서

## 총주행거리 수정 방법

### ⭐ 관리자 수동 수정 (권장 방법)

**"차량 기본 정보 수정" 기능을 통해 총주행거리를 직접 수정할 수 있습니다.**

1. 차량 상세 페이지에서 **"차량 기본 정보 수정"** 버튼 클릭
2. 로그인 정보 입력 (관리자 권한 필요)
3. **"총주행거리(km)"** 필드에서 원하는 값으로 수정
4. 저장 완료

**수정 후 동작:**
- 수정된 총주행거리가 새로운 기준값이 됩니다
- 다음 주유 입력 시, **수정된 값보다 큰 주행거리**만 입력 가능합니다

**예시:**
```
1. 마지막 주유 기록: 100km
2. 관리자가 "차량 기본 정보 수정"에서 총주행거리를 1km로 변경
3. 다음 주유 입력: 2km 이상이면 입력 가능 (1km보다 크면 OK)
4. 2km 입력 시 → 총주행거리가 2km로 자동 업데이트됨
5. 다음 주유는 3km 이상 입력 가능
```

## 과거 문제 해결 (2026-02-19)

### 문제 설명

차량 "경남81사6149"에서 총주행거리가 255,408 km로 잘못 표시되는 문제가 발생했습니다. 
이는 일일차 주행거리(248,507 km)보다 작아야 할 값이 더 큰 값으로 저장되어 있었습니다.

## 근본 원인

1. **데이터베이스 트리거 로직 문제** (scripts/051_create_universal_maintenance_trigger.sql)
   - 주유 기록이 추가될 때, `sync_refueling_to_vehicles()` 트리거가 자동으로 `total_mileage`를 업데이트
   - **문제**: 새로운 주유 기록의 주행거리가 현재 총주행거리보다 **작아도** 무조건 업데이트
   - 결과: 잘못된/낮은 주행거리 값이 입력되면 총주행거리가 **감소**하는 버그 발생

2. **데이터 불일치**
   - 과거에 잘못 입력된 주유 기록으로 인해 일부 차량의 총주행거리가 실제보다 낮게 저장됨
   - 이후 새로운 주유 기록을 입력하려 하면 "총주행거리보다 작습니다" 경고 발생

## 해결 방법

### 1. 트리거 로직 수정 (scripts/052_fix_total_mileage_update_logic.sql)

`sync_refueling_to_vehicles()` 함수를 수정하여:
- **새로운 주행거리 >= 현재 총주행거리**인 경우에만 `total_mileage` 업데이트
- 새로운 주행거리가 현재보다 작으면:
  - 경고 로그만 남기고 `total_mileage`는 업데이트하지 않음
  - 주유 날짜와 주행거리는 참고용으로만 저장

```sql
-- 핵심 변경사항
IF NEW.mileage_value >= COALESCE(current_total_mileage, 0) THEN
  -- total_mileage 업데이트
ELSE
  -- 경고 로그만 남기고 total_mileage는 유지
  RAISE WARNING 'Refueling mileage is less than current total_mileage. Skipping update.';
END IF;
```

### 2. 기존 데이터 수정 (scripts/053_check_and_fix_incorrect_total_mileage.sql)

모든 차량의 `total_mileage`를 다음 로직으로 재계산:
- 각 차량의 **모든 주유 기록 중 가장 큰 주행거리 값**을 찾음
- 이 값으로 `total_mileage`를 업데이트
- 잘못 감소된 총주행거리가 올바른 최대값으로 복구됨

### 3. 클라이언트 검증 강화 (maintenance-history.tsx)

주유 기록 입력 시 검증 메시지 개선:
- 더 명확한 오류 메시지 제공
- 콘솔 로그 추가로 디버깅 용이성 향상

## 적용 결과

### 데이터베이스 변경사항
1. ✅ 트리거 함수 업데이트: `sync_refueling_to_vehicles()`
2. ✅ 모든 차량의 총주행거리를 올바른 최대값으로 복구

### 동작 방식
- **이전**: 주유 기록 입력 시 주행거리가 감소할 수 있음 (버그)
- **이후**: 주유 기록의 주행거리가 증가하는 경우에만 총주행거리 업데이트

## 향후 방지책

1. **클라이언트 검증**: 주유 기록 입력 시 현재 총주행거리보다 작은 값 입력 불가
2. **트리거 보호**: 데이터베이스 레벨에서도 총주행거리 감소 방지
3. **로깅 강화**: 비정상적인 주행거리 입력 시 경고 로그 기록

## 영향받는 차량

이 수정사항은 **모든 차량**에 적용되며, 특히 다음과 같은 경우 영향을 받습니다:
- 과거에 잘못된 주행거리가 입력된 차량
- 총주행거리가 실제보다 낮게 표시되는 차량
- "일일차 주행거리가 총주행거리보다 크다"는 오류가 발생하는 차량

## 실행된 스크립트

1. `scripts/052_fix_total_mileage_update_logic.sql` - 트리거 로직 수정
2. `scripts/053_check_and_fix_incorrect_total_mileage.sql` - 기존 데이터 복구

## 확인 방법

수정 후 다음을 확인하세요:
1. 차량 목록에서 모든 차량의 총주행거리가 올바르게 표시되는지
2. 새로운 주유 기록 입력 시 정상 작동하는지
3. 낮은 주행거리 입력 시 적절한 오류 메시지가 표시되는지

## 시스템 동작 원리

### 총주행거리 업데이트 우선순위

1. **관리자 수동 수정** (최우선)
   - 위치: 차량 상세 페이지 → "차량 기본 정보 수정"
   - 권한: 로그인한 관리자만 가능
   - 효과: 즉시 데이터베이스에 반영, 다음 주유 검증 기준값이 됨

2. **주유 기록 자동 업데이트**
   - 주유 입력 시 자동으로 트리거 실행
   - 조건: 주유 주행거리 >= 현재 총주행거리
   - 효과: 조건 충족 시 총주행거리 자동 증가

### 주유 입력 검증 로직

```
입력값 검증 (클라이언트):
  주유 주행거리 < 현재 총주행거리 → 입력 거부 + 오류 메시지
  주유 주행거리 >= 현재 총주행거리 → 입력 허용

데이터베이스 트리거:
  주유 주행거리 >= 현재 총주행거리 → 총주행거리 업데이트
  주유 주행거리 < 현재 총주행거리 → 경고 로그만 기록
```

### 관리자 수정이 필요한 경우

다음과 같은 상황에서 "차량 기본 정보 수정"을 사용하세요:

1. **차량 초기 설정**: 새 차량 등록 시 실제 주행거리 입력
2. **오류 수정**: 잘못 입력된 총주행거리 강제 수정
3. **주행거리 리셋**: 계기판 교체 등으로 주행거리를 낮은 값으로 재설정
4. **데이터 복구**: 과거 기록이 없어서 수동 입력이 필요한 경우

**주의사항**: 관리자가 총주행거리를 수정하면, 그 값이 새로운 기준이 되어 이후 모든 주유 입력은 수정된 값보다 커야 합니다.
